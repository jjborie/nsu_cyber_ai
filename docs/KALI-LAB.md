# Optional Kali and PentestGPT exercise

This exercise is unexecuted until students collect actual evidence. Use a disposable Kali VM with a copy of this repository and the application running on the same VM's loopback interface. Use fictional data only. Limit the target to `http://127.0.0.1:5092`; do not scan university networks or public hosts.

Install Git, Python 3.12 or newer, and uv following their official instructions. Clone [PentestGPT](https://github.com/GreyDGL/PentestGPT) into an ignored local folder, retain its upstream license, and check out the reviewed reference `e8b1bb77d1ac00329675cec3b060aba971ec1ac8`. Run its `make install`, then inspect `pentestgpt --help` because backend requirements can change. Current upstream supports authenticated Claude/Codex backends. Configure those separately; no paid model calls are made by this repository. A local Ollama option is available in the legacy interface documented upstream.

Start the board with `dotnet run --project src/StudentLab -- --urls http://127.0.0.1:5092`. In a second terminal, run `LANGFUSE_ENABLED=false pentestgpt --target http://127.0.0.1:5092 --mode pentest --no-telemetry`. Supervise proposed actions: allow only the local target, bounded requests, and disposable board data. AI conclusions require reproduction; tool output alone is not a verified finding.

Concrete assignment: create a fictional experiment, then update/delete it from a second client without credentials. Retain request/response evidence. Explain why the shared anonymous classroom design permits this, and why private student records would require authentication and ownership checks. Map the scenario to OWASP A01:2025, CWE-862, and the selected ASVS authorization requirements in `security/framework-map.json`. Explain why ATT&CK data manipulation is a conditional integrity analogy rather than proof of an adversary campaign. Do not perform memory exhaustion; demonstrate missing item quotas by code review and a small bounded sample.

Register reproduced findings using the assurance `finding` command, linking evidence inside the run. Use `record` for a signed review note containing scope, author, method, observations, and gaps. Store transcripts locally, redact credentials, and preserve original evidence plus a linked retest. A student can add ownership checks, rerun the same two-client reproduction, and compare the results. Reports remain `not-run` for Kali/PentestGPT until this supervised activity is recorded; importing a transcript does not turn it into an automated passing gate.
